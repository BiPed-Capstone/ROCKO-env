# Make the repo easier to start in: fewer files, a shorter path to the open decisions

- **Date / commit:** 2026-11-26, built on `b33a781`
- **Branch:** `ai-forward`
- **Environment:** macOS laptop (host checks); dev container for the ladder where noted

The owner has no robot access and asked for cleanup that makes the repo easier for a new person and an agent,
removing and simplifying where that helps. The owner chose the order: D proposals, E unused files, A a start-here
guide, C the journal, B CLAUDE.md, F glossary and diagram, G code readability. One section per item below, each
added in the commit that does it.

## D. The proposals index shows what waits on the owner

**Goal.** A reader of [`docs/proposals/README.md`](../proposals/README.md) sees, in one table, the decisions still
waiting and in which order they help the robot; the decided ones are apart. No links break.

**What changed (docs only).**
- The index is split into *Waiting on you* (13 rows, ordered by what unblocks the next balance test, with a
  "Needs: robot or desk" column) and *Decided or superseded* (4 rows). Files keep their numbers and paths, so no
  link elsewhere changes; moving the closed ones to a subfolder was rejected for that reason.
- Dated status notes where a proposal names removed code: 0004 (file names after the BNO055 rename; the laptop
  heartbeat is gone; C-1 is fixed), 0012 (item 3, the keyboard speeds, is void), 0013 (option B is void; the
  question left is the dead band for balancing).

**Verification.** `python3 tools/check_doc_links.py`: 0 broken.

## E. Remove files nothing uses

**Goal.** Only one boot service exists in the repo; no doc describes the removed ones as installable; the host
test of the Pi scripts checks the new behavior and goes red when it breaks.

**What changed.**
- Removed `pi/rocko-tank.service` and `pi/rocko-dashboard.service`. `rocko.service` (the supervisor) replaced both
  on 2026-11-24 and has run on the robot since; installing it already removed them.
- `pi/install_boot_service.sh` installs only `robot`; any other name gets the usage. It still removes an old tank
  or dashboard unit left on a Pi, so an older Pi migrates the same way.
- `pi/launch.sh` checks only `rocko.service` in its launch guard.
- `tools/pi_scripts_test.sh`: the checks of the two old units are replaced by "tank, dashboard and balance are
  refused with the usage"; 26 checks.
- Removed `docs/claude-analysis/xbox-controller-macos-plan.md`: a plan, superseded on 2026-11-22 when the Mac
  program was deleted. The 2026-11-19 journal's two links to it are now plain text pointing at git history.
- Docs: the Pi guide, the bench guide, the drive guide, the dashboard guide, the supervisor page, the README's
  folder table, a comment in `Dashboard.py`. next-steps rows 4.11 and 4.12 (superseded by 4.13 on 2026-11-23)
  removed.
- Kept on purpose: `sim/results/stage5c2-*` (proposal 0008 cites them), `tools/measure_reversal_ramp.sh` (a
  measurement the owner may repeat), the root-level scripts (the allow-list names them by exact path).

## A. A start-here path, and a README that points instead of repeating

**Goal.** A newcomer finds one page that takes them from clone to a laptop running every check; the README says
where the project stands and where to go, and stops repeating procedures that have a guide. Every fact removed from the README is kept somewhere: in a guide or the
ladder.

**What changed (docs only).**
- New [`docs/guides/getting-started.md`](../guides/getting-started.md): clone, the dev container, the mount check,
  `tools/run_ladder.sh`, the simulated robot, a reading order, how to pick a task, working with Claude Code.
- New [`docs/glossary.md`](../glossary.md) (item F's first half, brought forward because the guide links it).
- `README.md`, 381 to 211 lines: a "where it stands" box, a "you want to... go to" table, the concepts and the
  signal path diagram (kept), the folder map without the 1,400-character `tools/` line, short build and run.
  Moved out: the laptop container walk-through (already in `verify-in-container.md` and the ladder), the ROS package
  list (`package.xml` is the source), `--symlink-install` and the stale skip-build fix (now in `run-on-the-pi.md`).
- `docs/README.md`, `docs/guides/README.md`: getting started first; each procedure's one home named.
- ADR 0003's link to the removed README section; the `bootstrap-sim` and `write-docs` skills' descriptions of the
  README.

**Verification.** `python3 tools/check_doc_links.py`: 0 broken. The guide's commands and expected output were
checked against the scripts (`run_ladder.sh` steps, `check_container_mount.sh`'s `ok` line, the container name in
`docker/compose.yml`, `joint_state_broadcaster` in `rocko_sim.launch.py`); the guide was not walked from a fresh
clone on a second machine.

**Review (one round).** `docs-reviewer`:
- the glossary's tipover and watchdog entries were wrong: the latch never re-arms by itself, and the watchdog zeroes
  the velocity reference, not the balancing;
- the README overclaimed that everything builds on a laptop (the motor plugin does not);
- six facts the cut had dropped: the debugging commands, `view_robot.launch.py`, `--packages-select`, the WiringPi
  install step, the mock's "nothing can move the wheels", the RViz caveat.

All are fixed; the first five facts are now in `run-on-the-pi.md` or the README. The RViz caveat was dropped, because
the ladder already lists `view_robot.launch.py` as not run.

`explainability-reviewer`:
- step 3 had no expected output;
- "controller" meant both the gamepad and a ros2_control controller;
- PWM, I²C and Docker were undefined;
- the pitch entry did not say which way is positive.

Fixed:
- step 3's expected output is copied from a run of `rocko_sim.launch.py` in the container (five controllers
  `active`, no `[ERROR]` lines, `/dynamic_joint_states` with `pitch`, `pitch_rate` and `velocity`);
- the USB device is "gamepad" throughout;
- glossary entries were added for PWM, I²C, Docker and ROS 2.

Declined:
- writing the pitch sign into the glossary: it depends on conventions the two measurement journals explain, and a
  one-line paraphrase would be easy to get wrong;
- moving the folder map out of the README: a front page is where a stranger looks for it.
